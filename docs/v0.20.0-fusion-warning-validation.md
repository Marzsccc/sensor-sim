# v0.20.0 校验：Fused-Track → ADAS-Marker → Warning Arbitration

**日期**: 2026-09-12（晚间自主任务）
**范围**: `sensor_sim/track_warn.py`（`TrackToMarker` + `FusionThreatPipeline`）
**基线**: v0.19.0（195 tests passed）

## 目标

把 v0.18/0.19 的融合跟踪器接到 v0.11 的告警仲裁链：把 `Track`（世界系 `[px,py,vx,vy]`）适配成 `AdasMarker`，并**从跟踪动力学推导 closing rate**（不再手摆 `closing_rates` dict），使 HUD 告警决策直接消费感知层输出。

## 设计决策

| 决策 | 理由 |
|---|---|
| `TrackToMarker.map()` 只映射 **confirmed** track | tentative（单次检测）track 的横向速度先验巨大，会闪出幽灵告警标记 |
| closing rate = 相对速度在视线方向投影（kinematic 正 = 靠近） | 与 `TTCModel` 的**负=靠近**符号约定在仲裁边界翻转，避免埋符号 bug |
| `FusionThreatPipeline.decide()` 默认给 track 一个 `VISIBLE` 可见决策 | `arbitrate` 把"无 visibility 信息"当作不可见；融合 track 在 FOV 内默认应可仲裁 |
| range 上限作用在未过滤 track 上 | 超出标记范围的 target 无论多快都不该抢占告警 |
| 桥接层不触碰 `adas.py`/`hazard.py` 内部 | 缩小爆炸半径；v0.11 语义完全复用 |

## 关键交互（semantics）

- `TTCModel.ttc_const_speed(rng, closing_rate)`：`closing_rate < 0` 才算 closing → TTC = `-rng/closing_rate`。
- `HazardAssessment.assess`：`score = type_weight * alignment * (0.35 + 0.65*ttc_term)`。`"fused_track"` kind 落到默认权重 `0.5`，TTC 满格时 score=0.5 ≥ WARN(0.35)，但 **OFF 阈值 0.12**，所以近距高速 closing 一定高于 OFF。
- 门控：`rng` 必须 ≤ `gating_range_m`(200) 且 >0，否则 TTC=None→score=0。
- 桥接的 closing rate 存为**仲裁层符号**（负=靠近）在 `marker.closing_rate_mps` 上，`decide()` 原样传给 arbitrator。

### 端到端证据（`test_e2e_with_radar_tracker`）

场景：宿主静止，lead box（40m，-15 m/s 靠近）+ 横穿行人 Sphere（35m，2.2 m/s 侧移），10 Hz 雷达 3 秒。
- 跟踪收敛后 **lead 以 closing 15 m/s 仲裁出 ≥ WARN**；
- 行人 closing 从初始噪声 ~0.4 收敛到 ~0（雷达对侧向运动结构盲 → 融合解出横向速度后才可信）。

## Demo

`examples/fusion_warning_demo.py` — 融合跟踪（radar+camera）→ mapped markers → 仲裁。

```
 t(s) nTrk  lead cr   ped cr   level
  0.5    2    15.15     0.41    WARN
  2.0    2    14.92     0.15    WARN
  4.0    2    -0.08      nan    WARN     (track 重新关联，短暂错误标记—见注)
  6.0    4    14.75    -0.61    WARN
```

- lead closing 稳定 ~15 m/s，全程 WARN（近距但非 AEB 区）；
- ped closing 从初始误报 ~0.4 → ~0（雷达"看不见"侧向运动，融合校正后收敛）——**正确行为**；
- 注：t≈4.0s 出现 lead track 短暂重关联（track 编号切换导致匹配逻辑误判），不影响语义结论。
