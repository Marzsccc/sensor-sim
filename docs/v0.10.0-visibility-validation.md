# v0.10.0 — Near-Field Marker Visibility, FOV Culling & Occlusion

**Module:** `sensor_sim/visibility.py` · **Demo:** `examples/visibility_demo.py`
**Tests:** `tests/test_visibility.py` (+10, total 89 passing)

## Problem (the v0.9.0 trap this closes)

`adas.py` projects markers with a pinhole model

    u = cx + f_px_x * y / x ,   v = cy + f_px_y * z / x

where `x` is forward range in the body frame. As an FCW/AEB hazard, a lead
vehicle, or a close obstacle approaches, its *pixel* footprint diverges:
at `x → 0` the projected coordinates fly to ±∞, producing flicker, an
off-screen box, or a numerically meaningless render right at the moment the
driver needs the marker most. The v0.9.0 uncertainty fade reduced *pose*
uncertainty but did **not** protect the *geometry* itself.

## Design

This module isolates the near-field decision so the render loop never lets a
divergent pixel flow downstream:

| Piece | Role |
|---|---|
| `Frustum` | HUD FOV frustum: hfov / vfov half-angles, `near_m` clip, `min_range_m` hard floor, `max_range_m`. Classifies a body point → `OK / NEAR_PLANE / TOO_CLOSE / OUT_OF_FOV / TOO_FAR / BEHIND`. |
| `angular_size` | Marker on-screen size in **degrees** instead of pixels. The angular span `2·atan(extent/r)` stays **finite for every r>0** — it is the divergence-proof counterpart to the pixel model, and it is what the eye actually resolves. |
| `Occluder` / `overlap_frac` | Bodywork / A-pillar / bonnet angular occupancy; fades a marker when the driver's own vehicle overlaps its projected angular footprint. |
| `MarkerVisibilityPolicy.decide` | Per-marker-per-tick render decision `FULL / FADED / CULLED` + alpha + machine-readable reason. **Culls BEHIND / TOO_CLOSE / OUT_OF_FOV / TOO_FAR before the pinhole projector runs.** |

The near-field fade gate is driven by **angular oversize**, not raw pixels:
when a marker's angular span exceeds `max_ang_deg`, alpha ramps down. This
is numerically safe (finite for all ranges) and matches perception.

## Validation

- **Close-in stability:** `angular_size([[0.8,0,0]], extent=0.9)` → pixel
  span explodes while angular span stays finite (≈96°). The gate fades
  instead of shattering.
- **Hard culls:** a 0.5 m hazard → `TOO_CLOSE` → CULLED, alpha 0. Behind
  and out-of-FOV markers likewise CULLED before any projection.
- **Near plane soft fade:** within FOV but past the near clip →
  `NEAR_PLANE` (drawable, fades progressively) — a fade, not a hard cull.
- **Angular-oversize demo:** hazard at 1.2 m ahead → **112.6° angular**
  span and only 3.0 px (the pixel quantity is meaningless here) → faded to
  α≈0.35 by angular oversize + bonnet occlusion.
- **Occluder fade:** lead/lane markers at ±40 m drop to α≈0.85..0.99 by
  the bonnet overlap; high (sky-side) markers stay opaque.

## Production lessons (for AR-HUD)

1. **Cull in the look frame before projecting to pixels.** Range, FOV and
   behind-ness are all cheap in the body frame; projecting first invites the
   divergence.
2. **Drive the near-field fade by angle, not pixels.** Pixel size diverges
   exactly where the driver needs the marker most; angular size is the
   convergent, physiologically meaningful metric.
3. **Bodywork occlusion is an intrinsic HUD property.** Fade markers the
   bonnet / A-pillars overlap rather than drawing them through the car.
