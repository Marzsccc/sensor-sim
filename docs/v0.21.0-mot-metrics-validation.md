# v0.21.0 — Ground-truth MOT metrics (OSPA / GOSPA / CLEAR-MOT)

*Status: complete. Full suite 214 → 252 passing (38 new).*

## Why

The v0.17–v0.20 stack (radar → detections → EKF tracks → ADAS markers →
warning arbitration) never answered the question a tracking team actually
asks in review: **"how good is the track set?"**  The v0.18 doc explicitly
left "GT-to-track metrics (OSPA / MOTA) reusing `RadarFrame` truth channels"
as a candidate roadmap item.  v0.21.0 fills it.

A single-number trap motivated doing it properly: on the v0.21 demo scene a
*naive* front-end (every raw detection promoted to a track) scores **MOTA =
1.000** because none of its targets were missed until we added one — MOTA
alone rewards raw detections and hides their jitter.  The metrics module
therefore ships **both** families: set-distance metrics (localisation-aware)
*and* identity/CLEAR-MOT metrics.

## What changed

### 1. `RadarFrame` now carries a full ground-truth channel

Previously `RadarFrame` only described the detections that survived the
Bernoulli detection draw — so a tracker's *false negatives* (missed targets)
were literally unobservable.  Two additive fields fix that without touching
any existing consumer:

| field | shape | meaning |
|---|---|---|
| `truth_ids` | `(M,)` int | id of **every** object inside the FOV + range gate, detected or not (`M >= N`) |
| `truth_points` | `(M, 3)` | sensor-frame truth *near-surface* reflection point (from true range + true bearing) of each in-gate object |
| `azimuths_true`, `elevations_true` | `(N,)` | per-**detection** truth bearing (pre-noise), aligned with `ranges` |

`RadarFrame.points_true` (detection-aligned truth) and the new
`RadarFrame.truth_world_points(origin_w, att_wxyz)` (all-gated truth, world
frame) round it out.  The truth row is recorded **before** the detection draw,
so missed targets survive into the frame.

### 2. New module `sensor_sim/mot.py`

Self-contained (no radar/tracker imports) so it can grade any tracker,
including a vendor black box.

**Set-distance metrics**

- `ospa(est_xy, gt_xy, cutoff, order=1.0, return_components=False)` —
  Schuhmacher–Vo–Vo OSPA: a single scalar penalising localisation error,
  missed targets and false tracks, with a cutoff `c` that caps the influence
  of far-away garbage.  Optimal (Hungarian) assignment on an `n_max×n_max`
  padded cost matrix; ordering-invariant; `0` iff the sets coincide.
- `gospa(est_xy, gt_xy, cutoff, order=1.0, alpha=2.0)` — the 2-α GOSPA,
  returned as `{total, localisation, missed, false}`.  Each component is a
  p-th root so that `total^p = loc^p + missed^p + false^p` (tested).

**Identity metrics**

- `assign(est_xy, gt_xy, gate=None, use_hungarian=True)` — one scan's
  estimate↔truth association; global (Hungarian) by default, greedy optional;
  gate forbids far pairings.  Unmatched-object cost is set so a within-gate
  match is always preferred over discarding either side, and a beyond-gate pair
  is always discarded (this was a real bug caught by the tests: a zero-cost
  "ignore everything" solution made the Hungarian path return *no* matches).
- `MotAccumulator(gate_m, cutoff_m, order, alpha)` — streaming CLEAR-MOT:
  `mota`, `motp`, `false_positives`, `false_negatives`, `id_switches`,
  `mean_ospa`, `mean_gospa` (+ decomposition), and — when ids are supplied —
  `mostly_tracked` / `partially_tracked` / `mostly_lost`.

**Radar-truth convenience**

- `truth_world_points(frame, host_pos, att_wxyz, mount_t_body=None)` — the
  `(M, 2)` world-frame truth set straight from a `RadarFrame`, mount offset
  included.

**Conventions** (documented + tested)

- `MOTA = 1 - (FP + FN + IDSW) / N_gt`; when `N_gt = 0` it is `1.0` if there
  were also no errors and `nan` otherwise (undefined ratio, not a free pass).
- `MOTP` = mean matched Euclidean distance (m) — a localisation score.
- GOSPA cardinality penalty per unmatched object is `c^p / alpha`.
- MOTA counts ID switches, so any identity metric is *always* reported next
  to an OSPA/GOSPA number.

## Demo

`examples/mot_demo.py` — one scene, two front-ends, the *same* radar truth.
Scene: closing lead (70 m, −4 m/s), off-axis car (45 m), crossing pedestrian
(30 m), and a **stopped car 100 m ahead** whose ~60% per-scan detection
probability is the whole point: the naive front-end loses it on every miss,
the EKF tracker coasts through the gaps.

```
=== CLEAR-MOT summary ==============================================
metric             naive       ekf
mota               0.910     0.994
motp               0.331     0.209
false_positives     0.000     1.000
false_negatives    29.000     1.000
id_switches        0.000     0.000
mean_ospa          1.018     0.252
mean_gospa         2.639     0.933
mostly_tracked         3         4
mostly_lost            0         0
```

Reading: the tracker quarters the mean OSPA (1.02 → 0.25 m) and cuts MOTP by
37% (0.33 → 0.21 m) while turning 29 missed targets into 1; its single FP is a
birth transient.  The naive row is exactly why localisation-aware metrics must
ship alongside MOTA.

## Conclusion

✅ v0.21.0 complete: the tracking stack can now be graded end-to-end against
radar ground truth, with missed detections observable for the first time.
214 → 252 tests pass; `ruff` clean on the new files modulo the repo's existing
typing-modernisation backlog.
