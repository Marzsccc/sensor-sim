# v0.6.0 — Error-State Kalman Filter (ESKF) for GNSS+IMU Loose Coupling

**Date:** 2026-08-13 (autonomous session)

## What was added

New module `sensor_sim/eskf.py` — a self-contained (numpy-only) 15-state
error-state Kalman filter for GNSS + IMU loose coupling, the classic
strapdown INS fusion formulation:

- Nominal state: `x = [p, v, q, b_a, b_g]` (position, velocity, attitude
  quaternion, accel bias, gyro bias)
- Error state: `dx = [dp, dv, dθ, db_a, db_g]` (15 dims)
- Prediction: IMU mechanization at high rate (nominal-state integration +
  first-order error-state covariance propagation, Solà 2017 eq. 178–180)
- Update: GNSS position + velocity, Joseph-form covariance update,
  innovation outlier gate (6σ rejection)
- Quaternion exponential/log maps for SO(3) error injection

## Validation

Run on a 60 s trajectory (10 m/s straight + 90° turn + straight) with
tactical IMU (100 Hz):

| Config | Position RMS (settled) | Position max | Velocity RMS | Yaw max |
|---|---|---|---|---|
| IMU dead-reckoning (no update) | 12.0 m | 35.5 m | — | — |
| **ESKF + automotive GNSS (5 Hz)** | **2.3 m** | 3.8 m | 0.05 m/s | 0.8° |
| **ESKF + RTK GNSS (10 Hz)** | **0.074 m** | 0.11 m | — | — |

Key observations:

1. ESKF beats pure dead-reckoning by 5–15×.
2. Fusion accuracy tracks the GNSS noise floor (automotive ~2.2 m incl.
   multipath; RTK ~7 cm) — the IMU smooths high-frequency noise without
   adding drift, exactly as theory predicts.
3. Accel/gyro bias estimates converge toward the true injected biases
   (velocity updates make accel-bias observable; turns make gyro-bias
   observable).
4. 6σ innovation gate rejects GNSS jumps (tested with a 1000 m outlier).

## Usage

```bash
python examples/eskf_demo.py          # automotive-grade, full report
python examples/eskf_demo_rtk.py      # RTK-grade, accuracy ceiling
```

```python
from sensor_sim.eskf import ESKF, ESKFConfig
eskf = ESKF(ESKFConfig(gnss_pos_std=2.2, gnss_vel_std=0.1))
eskf.set_initial_state(t0, p0, v0, q0)
# loop:
eskf.predict(acc_meas, gyr_meas, dt)          # 100 Hz
if gnss_valid:
    eskf.update_gnss(pos_meas, vel_meas)      # 5–10 Hz
```

## Design notes

- **Loose coupling** (position/velocity update) chosen for simplicity and
  robustness; tightly-coupled pseudorange updates would need raw GNSS
  observations — a possible v0.7 direction.
- **Joseph form** used for the covariance update to avoid asymmetry /
  negative eigenvalues under repeated updates.
- The filter consumes the same synthetic measurements produced by
  `IMUSensor`/`GNSSSensor`, so the whole package is a closed-loop
  sensor-model + estimator simulation — directly reusable for user's
  AR-HUD / 组合导航 algorithm work.

## Links to user's domain

- Same ESKF formulation is the core of most commercial GNSS+INS 组合导航
  products (RTK/PPK, vehicle navigation, AR-HUD pose fusion).
- The `predict.py` display-time pose predictor (v0.5.0) can be used as the
  *prediction* stage ahead of this ESKF's fused state.
